# 小六上架使用說明

在員工群組先 @ 小六或直接叫它，再傳這次的文字和圖片，傳完後再 @ 它說「好了」即可。
整段對話由模型理解，不用固定句型、制式欄位、預先標記用途、報張數或固定標點。
開頭叫名字後的文字不再比對命令關鍵字。真正的 LINE @、回覆它的訊息也都會交給模型處理。

例如：

> @小六（正常交代這次想做的事；下面只是例子，不是口令）
>
> 這本新劇本麻煩你放到官網，我把資料傳過來。
>
> （貼劇本介紹、人數、時間、售價、類型；角色名單有的話一起貼）
>
> （傳封面和所有角色圖）
>
> @小六 好了

也可以只先叫它，接著傳資料。小六先保存這一輪的文字和圖片，收齊後由 Opus 一起整理封面、角色圖及角色配對。
若先前已交代要上架，最後說「好了」就會接著完成；若從未說明這批要做什麼，它會問清楚目的，不會把每批資料都擅自發布。
你也可以說「接下來是封面」「第一張當封面」「這張是某某角色」，它會參考你的指定。
只有真的缺資料或圖片無法確定時才會詢問；回覆它那則問題，或叫「陸總」補答，即可沿用原本資料接續，不必重傳整批。

- 同一本由同一位員工在同一群組操作，避免不同人的資料混在一起。
- 只有直接叫小六或 @ 它、由模型判斷是這輪收件，才會收資料。提到它的名字不等於叫它，模型判斷為轉述時會保持安靜。
- 傳完、取消、失敗或閒置 15 分鐘後會停止收件，草稿與已存圖片仍保留。要繼續傳圖時說「陸總，繼續剛才那本」即可。
- 說「先幫我整理，還不要上架」可以先整理；之後說可以上架才會發布。
- 要看進度、取消或重試，請直接叫小六或回覆它的訊息，例如「陸總，目前收到哪些？」「陸總，先取消這筆」「陸總，再試一次」。
- 補圖或換封面，說明劇本名稱與要做的事，再傳圖即可。
- 每張圖片接受 JPG、PNG、WebP，最大 8 MB。成功保存的圖片可在失敗或重啟後繼續使用。

收到「資料已保存」表示已收件。**收到已上架及官網連結，才表示發布、同步與官網讀回已確認。**
若還在同步或連線失敗，原資料會保留；不要重新建立同名劇本。

## 維護說明

`listing_assistant.py` 管理原文、附件、同一任務的使用者授權與可恢復的收件狀態。
`listing_reasoner.py` 將完整原文及整批圖片交給目前設定的模型，透過 `prepare_listing` 回傳欄位與圖片配對。
`listing_workflow.py`、`listing_client.py` 保留欄位檢查、版本衝突保護、防重複發布與正式結果確認。
模型只能使用原始使用者文字作為操作授權；素材裡的文字不會成為發布指令。
