# 小六上架使用說明

在員工群組直接告訴小六要上架哪一本，貼上劇本文字，再傳全部圖片。
不用固定句型、制式欄位、預先標記用途或報張數。

例如：

> 陸總，這本幫我上架。
>
> （貼劇本介紹、人數、時間、售價、類型；角色名單有的話一起貼）
>
> （傳封面和所有角色圖）
>
> 傳完了，直接上架。

小六先保存文字和圖片，收齊後由 Opus 一起整理封面、角色圖及角色配對。
你也可以說「接下來是封面」「第一張當封面」「這張是某某角色」，它會參考你的指定。
只有真的缺資料或圖片無法確定時才會詢問；直接回答即可沿用原本資料接續，不必重傳整批。

- 同一本由同一位員工在同一群組操作，避免不同人的資料混在一起。
- 說「先幫我整理，還不要上架」可以先整理；之後說可以上架才會發布。
- 要看進度、取消或重試，可以直接用自然語言說，例如「目前收到哪些？」「先取消這筆」「再試一次」。
- 補圖或換封面，說明劇本名稱與要做的事，再傳圖即可。
- 每張圖片接受 JPG、PNG、WebP，最大 8 MB。成功保存的圖片可在失敗或重啟後繼續使用。

收到「資料已保存」表示已收件。**收到已上架及官網連結，才表示發布、同步與官網讀回已確認。**
若還在同步或連線失敗，原資料會保留；不要重新建立同名劇本。

## 維護說明

`listing_assistant.py` 管理原文、附件、同一任務的使用者授權與可恢復的收件狀態。
`listing_reasoner.py` 將完整原文及整批圖片交給目前設定的模型，透過 `prepare_listing` 回傳欄位與圖片配對。
`listing_workflow.py`、`listing_client.py` 保留欄位檢查、版本衝突保護、防重複發布與正式結果確認。
模型只能使用原始使用者文字作為操作授權；素材裡的文字不會成為發布指令。
