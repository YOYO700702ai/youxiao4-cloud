# 小六上架使用說明

## 一、管理員私訊上架（主要方式）

### 第一次：綁定帳號
用要當管理員的 LINE 帳號，私訊陸傲天（小六）**一則**訊息，內容就是維護者給你的那一行綁定碼（整則只放綁定碼）。
小六回「綁定完成」就好了，之後重新部署、重啟也不用再綁。

- 只有第一個用正確綁定碼的帳號會被綁定；綁定後別人再傳同一個碼也不會有反應。
- 沒綁定的帳號私訊小六（包括以前設定的群組擁有者帳號）：不回覆、不呼叫模型、不保存任何文字或圖片。
- 綁定碼打錯不會有任何回應。在群組或多人聊天室貼綁定碼不會綁定，那則訊息也會直接丟掉，不進任何紀錄。
- 原本的「[批量設性別]」指令改成只有已綁定的管理員私訊可用。
- 綁定碼不會進入模型對話或任何保存的資料。

### 之後：直接私訊聊天、交資料
私訊裡不用 @ 小六，每則都是給它的。
- 想聊天就聊天。
- 要上架時用自己的話說，例如「我要上架一本新的」，接著貼劇本文字、傳封面和角色圖，最後說「好了」。
- 不用固定口令、不用先標記哪張是封面、不用報張數。哪些文字和圖片屬於同一本、封面和角色怎麼配對、資料是否齊全，都由模型（Claude Opus 5.5）讀完原文和所有圖片後自己判斷。
- 連續貼好幾段時，小六會等你停一下再一起回，不會每則、每張圖都回一次；圖片會安靜收下。
- 真的缺資料時它才會問你。

收到「✅ …已上架」和官網連結，才表示官網發布並確認頁面完成；看到「⚠️」代表還沒確認，原資料都保留，請直接問它「剛剛那本好了嗎」，它會查詢結果或接續同一筆，不會重複新增。

## 二、群組

群組裡要先叫小六（LINE @、回覆它的訊息、或開頭叫「小六／陸總」），它才會處理。
模型判斷你要開始交資料時會開始收件；之後 15 分鐘內你沒叫它的文字和圖片也會安靜保存（只收你本人的），傳完再叫它說「好了」。
剛叫完它馬上傳的圖片（3 分鐘內）也會收。沒叫它時的一般聊天不會被收成素材，也不會回覆。
同一群組不同人的資料完全分開。

## 三、共通規則

- 每張圖片接受 JPG、PNG、WebP，最大 8 MB。某張存失敗不影響其他張；之後每次叫它都會自動重試，不用重傳、不用說特定的話。
- 舊的資料只當參考；換一本新書不會沿用舊書的書名、價格、角色、圖片或發布同意。
- 圖片裡的文字、轉貼的教學或指令截圖只是資料，不會被當成要它做事的指令。
- 新增劇本若官網已有同名，官網會拒絕，不會重複建立；修改既有劇本時會核對版本，避免蓋掉別人的修改。
- 私訊目前不能下架劇本；下架請由後台處理。

## 維護說明

- 設定環境變數 `PRIVATE_ADMIN_BIND_CODE`（至少 20 字元、高亂度、不要放進程式碼或聊天紀錄）。未設定或太短時，私訊綁定功能關閉。`/health` 的 `X-Private-Admin` 會顯示 yes/no（不含碼本身）。
- 綁定紀錄存在官網 bot jobs 儲存的 `('private-admin-binding-v1',)`，只存 LINE 帳號的雜湊值。要換管理員帳號：清除這筆紀錄並更換綁定碼。
- `admin_binding.py`：一次性綁定與管理員判斷（先到先得，用儲存的版本號防止兩個帳號同時搶綁）。
- `direct_material_agent.py`：每位使用者自己的原始對話紀錄（文字、圖片、工具收據），與一般的 Claude 原生工具對話。沒有書籍狀態機、圖片分類或完成判斷程式；私訊與群組的紀錄分開存。
- `direct_catalog_tools.py`：`catalog_lookup / catalog_publish / catalog_update / catalog_status`。只檢查：圖片必須是這位使用者自己已保存的圖、寫入必須引用這次的真實文字要求、官網版本號、冪等重送、發布後讀回確認。
  - 每個實際寫入請求送出前的那一刻都會再確認使用者沒有傳新訊息；有的話就不送。
  - 接續時一律先讀官網狀態再決定：草稿結果不明 → 用同一個冪等編號重送草稿；版本未發布 → 發布；已發布但同步失敗 → 走 `/sync` 重試同步；已發布 → 不再發布。`catalog_status` 只讀不寫。
  - 收據在取得草稿版本後就丟掉完整內容，並限制總大小；結果不明的操作會保留完整內容以便安全重送。
- 舊上架資料中有編號但沒存成功的圖片，之後每次對話會重新下載，每張最多試 5 次。
- `app.py`：私訊只有已綁定帳號會進到模型；群組只有叫到小六才會開模型對話。模型回合在背景執行，不佔住 LINE webhook。
- 舊的 `listing_assistant.py`、`listing_workflow.py`、`listing_reasoner.py`、`catalog_updates.py`、`ScriptWorkflow` 已不在任何執行路徑上，只剩舊測試引用。
